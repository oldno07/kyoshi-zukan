# モバイル・ファーストビュー改善｜EC導線コンパクト化 実装メモ

日付：2026年7月28日
ブランチ：`claude/mobile-firstview-ec-redesign-f1l7y6`
対象：個体ページ `astro-src/src/pages/zukan/[slug].astro`

## 依頼内容（要旨）

モバイル表示で、個体ページのファーストビュー〜直後の情報優先順位を

1. 個体名
2. 個体写真
3. BIOLOGICAL STATUS
4. コンパクトな譲渡（EC）導線
5. 解説テキスト

の順にする。既存の大きなECパネルをそのまま移設するのではなく、**モバイル専用にコンパクト再設計した簡易導線を追加**し、既存パネルは削除・移動せず維持する（デスクトップは現状維持）。

## 実装内容

### 追加した要素

`BIOLOGICAL STATUS`（`.cd-status`）セクション直後、`.cd-body`（解説本文）の直前に、モバイル専用の一行ブロックを追加。

- クラス名：`.cd-transfer-mini`
- 表示条件：`.cd-shop-panel` / `.cd-shop-soldout` と同じ frontmatter 条件（`data.shopUrl && !data.soldOut` / `data.soldOut`）
- 入手可能時：`TRANSFER / 譲渡` ラベル＋価格（または「譲渡局で開示」）＋「この個体を迎え入れる →」の1行CTA
- 完売時：`SPECIMEN / 標本` ラベル＋取り消し線付き `SOLD OUT`。CTAは付けていない（遷移先データが存在しないため、ダミーリンクは作らなかった）

### 表示制御

- デフォルト（デスクトップ）は `display: none`
- `@media (max-width: 768px)`（既存のモバイル分岐と同じブレークポイント）内で `display: block` にして表示
- 左右パディングは同ブレークポイントの `.cd-hero-l` / `.cd-status` / `.cd-body` と揃えて `24px` に統一

### 既存要素への影響

- `.cd-shop-panel` / `.cd-shop-soldout`（ページ下部の大きなECパネル）は**マークアップ・CSSともに一切変更していない**。デスクトップ・モバイルどちらでも従来通り表示される
- `git diff` は新規セレクタの追加のみで、既存セレクタへの変更なし（CLAUDE.md の「CSS変更の禁止」ルールに沿い、コミット前に確認済み）

## デザイン判断

- 大きなパネルを縮小コピーするのではなく、`.cd-data-row` のような「情報行」に近い見た目（細い罫線＋monoフォント）にして、"販売広告" ではなく図鑑データの一部に見えるようにした
- アクセントカラーは既存ECパネルと同じ `var(--g)` を流用し、世界観を変えていない

## 動作確認

- `npm run build` 成功（全32ページ生成）
- Playwright（Chromium, viewport 390×1200）で以下を確認
  - モバイル：入手可能個体（001）でコンパクト導線が表示され、BIOLOGICAL STATUSの直下・解説の直前に配置されている
  - モバイル：完売個体（005）で更にコンパクトな1行（CTAなし）が表示される
  - デスクトップ（1400px）：コンパクト導線は非表示、既存の大きなECパネルは従来通り表示される
  - モバイルでもページ下部までスクロールすると既存の大きなECパネルが変わらず存在する

## 追記（同日）：ファーストビュー未圧縮の修正

初回実装後、レビューで「①〜③（個体名・写真・BIOLOGICAL STATUS）がファーストビューに収まっていない」との指摘。実測したところ、主要モバイル機種でBIOLOGICAL STATUS終端が画面外に出ていた（iPhone SE: 861.5px、iPhone12/13: 876.5px、いずれも画面高さ超過）。

### 原因

- `.cd-hero-r`（写真エリア）が上下パディング32px×2＋ほぼ正方形の画像でモバイル幅の約9割を占め、単体で約390px消費していたのが最大要因
- `.cd-hero-l`（名前エリア）の上下パディングが40px×2と大きめ
- `.cd-status`（BIOLOGICAL STATUS）の内側余白・行間にも縮小余地あり

### 対応（`@media (max-width: 768px)` 内のみ変更、デスクトップは無変更）

| 要素 | 変更前 | 変更後 |
| --- | --- | --- |
| `.cd-hero-l` padding | `40px 24px` | `24px 24px 20px` |
| `.cd-hero-r` padding / min-height | `32px 24px` / `300px` | `16px 24px` / `0` |
| `.cd-cover` max-height | （制限なしでほぼ全幅正方形） | `200px` |
| `.cd-status` padding | `24px` | `16px 24px` |
| `.cd-status-title` margin-bottom | `20px`（共通） | `12px`（モバイルのみ上書き） |
| `.cd-bars` gap | `14px`（共通） | `8px`（モバイルのみ上書き） |

### 実測結果（BIOLOGICAL STATUS終端のy座標、ページ最上部からの距離）

| 機種 | 修正前 | 修正後 | 画面高さ |
| --- | --- | --- | --- |
| iPhone SE (375×667) | 861.5px | 630.5px | 667px |
| iPhone 12/13 (390×844) | 876.5px | 630.5px | 844px |
| Android Pixel系 (412×915) | 898.5px | 630.5px | 915px |

3機種いずれも①〜③がファーストビュー内に収まることを確認。コンパクト譲渡導線（④）もその直下、画面下端付近〜わずかに超える位置に配置され、「圧迫しない」要件も維持。

デスクトップの `computedStyle`（padding/min-height/max-height）が変更前と一致することも確認済み。

## 追記（同日）：個体名が2行に折り返す問題の修正

上記の圧縮後、実機確認（https://pelicanworks.site/zukan/011-filigrizzly-monarch/ ）で「フィリグリズリーモナーク」のようなカタカナ12文字の個体名がモバイル幅で2行に折り返してしまうとの指摘。

### 原因

`.cd-name-jp` のフォントサイズは `clamp(35px, 5vw, 64px)`（PC/モバイル共通）で、モバイル幅では下限の35px固定になる。一方コンテナ幅（`.cd-hero-l` の左右パディング24px×2を差し引いた幅）はiPhone SEで327px、iPhone12/13で342px程度しかなく、フルワイド文字12文字（≒1文字1em換算で420px相当）を収めるには全く足りず、必ず2行に折り返していた。

サイト内の最長の個体名は12文字（「フィリグリズリーモナーク」「スカイブルーニャンダホー」）。

### 対応

実測で「12文字が1行に収まる最大フォントサイズ」がビューポート幅から一次式で近似できることを確認（`(viewportWidth - 48px) / 12` にほぼ一致）。これに安全マージンを載せて、`@media (max-width: 768px)` 内に `.cd-name-jp` のフォントサイズを上書きする専用ルールを追加。

```css
.cd-name-jp { font-size: clamp(18px, calc(8.3vw - 6px), 30px); }
```

デスクトップ側の `clamp(35px, 5vw, 64px)` はそのまま。

### 実測結果（12文字の個体名 × 各幅で1行に収まるか）

| 幅 | フォントサイズ | 結果 |
| --- | --- | --- |
| 320px | 20.56px | 1行 |
| 360px | 23.88px | 1行 |
| 375px | 25.13px | 1行 |
| 390px | 26.37px | 1行 |
| 412px | 28.20px | 1行 |
| 428px | 29.52px | 1行 |

「フィリグリズリーモナーク」「スカイブルーニャンダホー」の両方で320〜428px幅すべて1行表示を確認。デスクトップ幅（1400px）では `.cd-name-jp` のフォントサイズが64pxのまま変わらないことも確認済み。
