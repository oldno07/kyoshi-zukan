`src/pages/admin/index.astro`、`public/js/admin.js`、
`functions/api/admin/subscribers/[speciesId].js`（新規）、
`functions/api/admin/unsubscribe.js`（新規）

## 変更前の前提

admin画面（`/admin/`）は種ごとの通知待ち人数（集計値）しか表示しておらず
（`GET /api/admin/subscribers` が species_id ごとの active_count / last_notified_at を
返すのみ）、個別のメールアドレスを確認する手段がなかった。これまではCloudflare D1
コンソールで直接SQLを実行して確認する運用だった。

## 変更後の内容

### 1. 新規API `GET /api/admin/subscribers/:speciesId`
指定した species_id の購読者明細（id / email / created_at / unsubscribed_at /
last_notified_at）を `created_at DESC` で返す。既存の集計API
`subscribers.js`（集計）とは別ディレクトリに分離し、混同を避けた。

### 2. 新規API `POST /api/admin/unsubscribe`
`subscriptionId` を受け取り、論理削除（`unsubscribed_at` の更新）のみを行う。
物理削除エンドポイントは作らない方針。対象なし・既に停止済みの場合も200で
`{ status: 'not_found' }` を返す（既存の `functions/api/unsubscribe.js` と同様、
`unsubscribed_at` の更新には `datetime('now')` を使用し、既存コードのスタイルに合わせた）。

### 3. admin/index.astro
各行に「詳細」ボタンを追加し、クリックで行の下に購読者一覧のサブテーブル（トグル式、
初期非表示）を展開表示するようにした。列はメールアドレス / 登録日 / 配信停止日 /
最終通知日 / 操作。デザインは既存の `:root` CSS変数（`--g` `--red` `--ink` `--mono` 等）を
流用し、ページ内scoped styleへの追加のみで対応（`global.css` / `style.css` など共有CSSは
未変更）。

### 4. admin.js
「詳細」ボタンで未取得時のみ `/api/admin/subscribers/:speciesId` をfetchしてキャッシュし、
再度開くときは再fetchしない。「配信停止」ボタンは `/api/admin/unsubscribe` にPOSTし、
成功後は該当行のボタンを disabled 化して「停止済み」表示に切り替える。既存の
`sendNotify` / `loadCounts` と同じ try-catch + `showMsg` のエラー表示パターンを踏襲した。

## 理由

D1コンソールでの都度確認作業をadmin画面に統合するため。

## 保留・未決事項

- 物理削除機能はUIに含めない方針。今後必要になった場合は別途指示書を起こす。
- Cloudflare Access による `/api/admin/*` の保護は、新規追加した
  `functions/api/admin/subscribers/[speciesId].js` と `functions/api/admin/unsubscribe.js`
  もパスパターン上は同じ保護範囲に含まれるはずだが、Access設定はCloudflareダッシュボード側の
  設定でありコード上からは確認できない。ダッシュボード側で経路が実際に保護されているか、
  デプロイ後に別途確認が必要。
